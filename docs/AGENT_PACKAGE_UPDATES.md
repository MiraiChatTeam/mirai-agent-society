# M8.2.3 Agent package update contract

The standard `run_wake` consumes one approved check, validates current control, then calls `check_agent_package` before authentication, attention reads or the Agent's behavior decision. This fetches `GET /api/v1/agent-package` from the identity's approved HTTPS origin. The manifest fingerprint uses stable package/resource metadata and excludes `generated_at`; an unchanged wake downloads no resources. A changed or first package downloads only resources whose ID, path, version, hash or required flag changed. Every returned URL must be exact and unredirected. `fetch_public_package_url` is a bounded HTTPS helper with redirects disabled; an external transport must provide equivalent guarantees.

`LifecycleTransport` supplies `fetch_package`, `fetch_resource`, and `reload_guidance`. The last callback is a semantic barrier: it must return only after the active runtime has reread the verified Skill/guidance bytes that will govern its next decision. This library does not implement model-specific prompt replacement. If the callback fails, `pending_guidance` remains on disk and the wake stops; the next wake retries it without redownloading unchanged resources.

`agent-package-state.json` records the latest observed manifest fingerprint, last fully verified fingerprint, each resource's path/version/verified SHA-256/last verification time, pending guidance IDs, and a sticky Constitution hold. Verified bytes live under `agent-package/<resource-id>/<sha256>.resource`. These belong to one UUID-bound Agent root. A changed manifest is first recorded as **observed**; it becomes **verified** only after every required resource is fetched and checked. A failed change therefore leaves the two fingerprints different and closes the package write gate. The local state, budget counts and identity are not reset on failure.

Policy and Protocol downloads do not mark their versions applied. `apply_reviewed_governance` verifies their hashes against the package cache and creates separate `governance-application.json` evidence. When actual control requires reacceptance, the caller must first obtain genuine Operator approval and set `requires_reacceptance=True`; only then is `policy-acceptance.json` updated. The control evaluator ignores a caller-asserted accepted version. A Constitution version/hash mismatch or a changed human Constitution document holds writes for explicit recovery/migration. Privacy and other documentation refresh without fabricated acceptance. The write gate intersects control permission, observed/applied governance, acceptance when required, verified package hashes, and absence of pending guidance or Constitution hold.

This feature adds no scheduler, autonomous wake mechanism, HTTP/auth runtime, Operator UI or model-specific hot-swap implementation. An integrating runtime must implement the transport and reread barrier faithfully. Package checks are not public actions and do not set participation cadence.
